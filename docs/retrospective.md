# Findex 프로젝트 회고록

> 저장소의 코드·이슈·PR을 바탕으로 정리한 회고 초안입니다. 개인별 소감과 팀의 최종 평가는 팀원 확인 후 보완합니다.

## 프로젝트에서 구현한 것

금융위원회 Open API 연동을 중심으로 지수 정보와 일별 데이터를 관리하고, 관심 지수의 성과를 조회하는 백엔드를 구현했습니다. 수동·자동 수집, 연동 이력, 차트 데이터 조회, CSV 내보내기를 하나의 서비스로 연결했습니다.

## 개발 과정에서 해결한 문제

### 1. 같은 이름의 지수가 서로 다른 분류에 포함되는 문제

외부 API를 지수명으로 조회하면 다른 분류의 동명 지수가 응답에 섞일 수 있었습니다. 응답을 받은 뒤 지수 분류명과 지수명이 모두 일치하는 항목만 저장 대상으로 선택하도록 수정했습니다.

외부 API의 검색 조건과 내부 데이터의 식별 기준을 함께 확인해야 한다는 사례입니다. 향후에는 동명 지수 응답을 포함한 회귀 테스트를 추가할 수 있습니다.

근거: [PR #26 — 지수 데이터 연동 버그 수정](https://github.com/ssibssaggi/sb14-findex-ssibssaggi/pull/26)

### 2. 같은 기간을 다시 연동할 때 발생하는 데이터 중복

이미 저장된 지수와 기준일의 데이터를 다시 삽입하는 방식은 재연동 시 중복 문제를 만들었습니다. 지수 정보와 기준일로 기존 데이터를 확인하고, 있으면 갱신하고 없으면 생성하는 방식으로 변경했습니다.

반복 실행할 수 있는 연동 기능은 재시도와 재수집을 처음부터 고려해야 합니다. 동일 기간 재연동과 여러 요청이 동시에 들어오는 상황은 추가 검증 대상으로 남아 있습니다.

근거: [이슈 #40 — 데이터 중복 연동 시 에러](https://github.com/ssibssaggi/sb14-findex-ssibssaggi/issues/40), [PR #41 — 지수 데이터 연동](https://github.com/ssibssaggi/sb14-findex-ssibssaggi/pull/41)

### 3. 지수 데이터와 연동 이력의 저장 단위

수집한 데이터와 성공 이력이 서로 다른 결과로 남지 않도록 `IndexDataSyncService`에서 함께 저장하도록 구성했습니다. 해당 빈의 저장 메서드에는 `REQUIRES_NEW`를 적용하고, 실패 이력 저장에도 별도 트랜잭션을 적용했습니다.

수집 결과, 데이터 저장, 작업 기록의 책임과 트랜잭션 범위를 구분하는 과정이 필요했습니다. 다음 단계에서는 데이터 저장 실패와 이력 저장 실패를 각각 재현해 롤백 범위를 검증할 수 있습니다.

근거: [PR #46 — 연동 실패 처리](https://github.com/ssibssaggi/sb14-findex-ssibssaggi/pull/46), [IndexDataSyncService.java](../src/main/java/com/ssibssaggi/findex/application/indexintegration/IndexDataSyncService.java)

### 4. 정렬 조건과 다음 페이지 커서의 일관성

지수 정보와 연동 이력 목록에서 여러 정렬 조건을 지원하면서 마지막 행의 정렬값을 다음 페이지에 전달하는 처리가 필요했습니다. 정렬값과 ID를 함께 사용하도록 구성했고, 대상 날짜가 없는 지수 정보 연동 이력에는 커서용 문자열을 반환하는 처리를 추가했습니다.

커서는 단순히 마지막 ID를 전달하는 기능이 아니라, 정렬 규칙과 데이터의 빈 값 처리까지 함께 정의해야 하는 API 계약입니다. 같은 정렬값이 반복되는 경우와 마지막 페이지에 대한 검증을 보강할 수 있습니다.

근거: [PR #21 — 지수 정보 동적 조회](https://github.com/ssibssaggi/sb14-findex-ssibssaggi/pull/21), [PR #25 — 연동 이력 조회](https://github.com/ssibssaggi/sb14-findex-ssibssaggi/pull/25)

## 협업 과정

기능별 이슈와 PR을 통해 담당 영역을 나누고, 대시보드·공통 코드처럼 연결되는 영역은 함께 통합했습니다. 공통 응답 형식과 Swagger 명세를 구성해 API 요청·응답을 확인할 수 있게 했습니다.

Checkstyle, 커밋 메시지 Hook, IntelliJ 공통 설정을 추가해 코드 스타일과 커밋 규칙을 개발 환경에서 적용하도록 구성했습니다. 실제 협업 효과와 개선 의견은 팀 회고에서 보완할 항목입니다.

근거: [이슈 #7 — 코드 품질관리 자동화](https://github.com/ssibssaggi/sb14-findex-ssibssaggi/issues/7), [PR #13 — 공통 응답과 예외 처리](https://github.com/ssibssaggi/sb14-findex-ssibssaggi/pull/13), [PR #45 — Swagger 명세](https://github.com/ssibssaggi/sb14-findex-ssibssaggi/pull/45)

## 개선 제안

아래 항목은 현재 코드와 개발 기록을 바탕으로 한 제안이며, 확정된 후속 일정은 아닙니다.

| 영역 | 다음에 검토할 작업 |
| --- | --- |
| 자동 수집 | 현재 10초 고정 주기를 운영 목적에 맞는 cron 설정으로 전환하고, 휴장일·외부 데이터 반영 시점을 고려 |
| 외부 API | HTTP 오류·응답 오류·빈 결과를 구분하고, 실패 이력 및 재시도 정책 정리 |
| 데이터 검증 | 중복 수집, 기간 경계, 정렬·커서, 이동평균 계산에 대한 자동화 테스트 보강 |
| 조회 성능 | 관심 지수 수와 데이터량이 증가할 때 실행 쿼리와 응답 시간을 측정해 개선 대상 선정 |
| 운영·문서 | 배포 URL, 시연 이미지·영상, 최종 발표자료를 연결하고 새 환경에서 실행 절차 확인 |
